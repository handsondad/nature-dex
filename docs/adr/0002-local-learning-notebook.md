# ADR-0002: 用受控目录与本地 SQLite 支持学习到图鉴的首个后端闭环

**状态**：草案（已实现，待审查）
**日期**：2026-10-28
**决策者**：项目维护者（待审查）

## 背景

孩子需要先查询学习，形成想去观察的兴趣，再记录真实发现、制作自己的图鉴。现有后端已有物种目录和发现台，但聊天只返回通用摘要，观察成果在重启后丢失。首版应验证这一完整流程，而不是先引入复杂模型基础设施或公开儿童社区。

## 决策

- 使用受控目录字段回答介绍、特征、比较、分类标签、季节和环境问题；返回知识卡和所使用的字段。对目录不支持的问题返回明确的知识缺口。
- 目录仍是内置样本，不把现有混合分类标签伪装成完整的分类树，也不伪造权威来源。
- 在 Agent 应用层编排学习、寻找清单和个人图鉴。API 不直接操作存储。
- HTTP 服务用本地 SQLite 保存观察、寻找清单和图鉴；复用同步观察仓储端口，并在线程池执行 I/O。新图鉴仓储提供异步接口。
- 图鉴必须关联孩子自己的观察快照，儿童原话和目录知识分开；未知发现可制作图鉴，但不自动确认。重复制作不覆盖已编辑内容。
- 会话和未保存草稿仍为进程内状态，不支持多进程共享。开发服务默认只监听本机。

## 理由

本地数据库不新增运行依赖，能验证重启恢复、重复提交和儿童间误引用处理。字段问答有明确的事实边界，在尚无审核资料库与模型安全策略时，不以未经支持的自然语言推理冒充科学解释。

## 备选方案

- 继续只用内存：最简单，但不能可靠保存孩子的创作成果。
- 立即引入 PostgreSQL、向量库与通用 LLM：适合后续生产化，但扩大了首个闭环的部署和内容审核范围。
- 自动把每次问答生成图鉴：会混淆学习资料与真实观察，也夺走孩子自己的表达。

## 影响

可以在本地完成学习、寻找、观察、制作、编辑和回看，并通过临时文件与重建 Agent 验证持久化。SQLite 内容由 Pydantic 模型序列化，当前只创建新表，无既有持久化数据迁移。

这不是可上线的儿童多人服务：尚无账号认证、家长授权、媒体上传清洗、公开分享、导出或真正的 LLM/RAG。`child_id` 仅用于分组与引用校验，不是访问凭证；`private` 仅表示没有发布功能。不得向公网开放或用于真实儿童数据的多人服务。后续替换存储、引入认证与审核知识来源时，需要新的 ADR。
